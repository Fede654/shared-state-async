# Post-expiry behaviour — what the corrected instrument shows

Generated by `experiments/post_expiry.py`. Supersedes an earlier attempt
whose conclusion was withdrawn in full; see
`../post-expiry-superseded/README.md` for why none of those five runs is
citeable.

## What changed in the instrument

| defect | fix |
|---|---|
| failed probes recorded as absence, so a crashed daemon could manufacture "extinction" | probe success/error recorded separately, liveness checked on any node reporting nothing, affected rows invalidated |
| no no-probe control, while probing displaced the gossip that prevents disappearance | `--control` arm samples only at the window's two ends |
| `spread/TTL` used uncorrected `spread_raw` | first-order skew correction applied, raw kept alongside |
| "mesh-wide extinction at time X" asserted simultaneity across rows spanning up to 24 s | rows now span ≤8.2 s and the quantity is renamed **quiescence**; per-row spans recorded |
| n=5 mixed two script versions, one uncommitted | one committed script; any run whose dependency manifest moves mid-run is excluded |

## Runs

Treatment = probed every ~8 s. Control = 2 probes total. 5-node chain,

## What this establishes

**The disappearance is not an artefact of observation.** All three
controls, carrying two probes each instead of ~37, still found the entry
absent at t≈305 s. That was the open possibility — that heavy probing
starved the gossip which would otherwise keep the entry alive — and it is
now ruled out for the endpoint.

**Organic resurrection was NOT reproduced.** Zero resurrections in three
valid treatment runs. Note this corrects a defect in the *metric* as well:
the superseded runs reported "4 resurrections" in every run, which was
simply the four non-author nodes receiving the entry for the first time.
A resurrection now requires present → absent → present again.

## What this does NOT establish

- **That resurrection does not happen organically.** T24 proves the
  missing-key path accepts an own-authored remote entry deterministically,
  with an echo TTL *below* the author's own insert TTL. And one
  observation exists: in superseded run base-0 the author held TTL 2 at
  t=29.0 s and TTL 1 at t=45.4 s, which is only possible if an entry
  arrived after expiry — the author publishes once. That reading is forced
  by the recorded TTLs regardless of that run's absence-detection bug, but
  the run used an uncommitted script and is not citeable as evidence.
  **Three corrected runs did not reproduce it.**
- **That the loop is self-limiting.** Absence of resurrection in three
  short runs is not proof that resurrection cannot sustain. The earlier
  "extinct in 5 of 5, therefore self-limiting" is withdrawn and is not
  replaced by anything.
- **Anything about production.** This cell runs interval/TTL = 5/20;
  production is 30/2400, twenty times smaller, so an entry here gets far
  fewer gossip opportunities per lifetime — plausibly the deciding factor.
  The earlier scale-transfer argument compared uncorrected `spread/TTL`
  against a "field range" that is itself an unsupported five-minute
  extrapolation. Withdrawn entirely.

## Remaining limits

- Three valid treatment runs, three controls, one topology, one cell.
- Controls give endpoints only, so they bound the *result*, not the
  *trajectory* — they cannot say when the entry disappeared.
- Rows span up to 8.2 s against a 24 s insert TTL. Better than the 24 s
  spans of the superseded runs, but still a smear: quiescence means
  nothing was found across many consecutive spans, not a simultaneous
  snapshot.
- The author never republishes. This is the "author went away" case.
- A production-TTL run has not been attempted and is the only thing that
  would settle transfer.
